# Experimental compact sidebar hover

**Zentral Settings → Advanced → Experimental → Stabilize Compact Tab Sidebar Hover (Experimental)** is the master switch for this sidebar guard and the window-entry enhancements below. It defaults to off and applies live. Turning it off releases protection, detaches pointer and lifecycle listeners, removes owned native method wrappers, and disables panel entry reveal. Child choices are retained for re-enabling. If another mod has wrapped a method after Zentral, its wrapper is preserved and Zentral's retained callback passes through while disabled. Ordinary Zen hover and existing Zentral panel autohide remain available.

## Sidebar hover guard

The guard prevents delayed native hover-removal callbacks from hiding an already hovered tab sidebar while the pointer remains inside its visible bounds. Leaving the window from the sidebar preserves hover for up to 1500 ms. Native outside-tracker cleanup, deactivation, resizing, compact-mode changes and drag start end protection. Returning to page content uses the normal sidebar keep-hover delay.

The live sliders control edge tolerance (0–64 px, default 12) and exit grace (0–2000 ms, default 250). The tolerance protects an already visible sidebar; it does not enlarge the hidden sidebar's reveal area. Zen's sidebar keep-hover duration remains a minimum delay. Slider changes apply to subsequent hit-tests and exits without resetting an active grace timer. Sliders are unavailable when the master is off.

## Window entry reveal

**Reveal Compact Tab Sidebar on Window Entry (Experimental)** defaults to off and requires the master and native compact sidebar hover. A trusted `mouseenter` on the document root reveals the sidebar when the reported crossing is at its docked left/right window edge and within its height. Child-element entries, opposite-side and top/bottom entries, dragging, floating URL bar suppression and native hover suppression do not trigger it. Entry from outside does not require an earlier exit recorded by Zentral.

A 10 px tolerance classifies a boundary event when no recent exit is known. A recent exit through the sidebar side is remembered separately from visibility for up to 1500 ms. The first trusted return event can then reveal the sidebar even when the root entry event was missed or the first cursor position lands deeper inside the matching half of the window. The evidence is consumed on that first return, so later ordinary movement cannot reveal the hidden sidebar. No hover-to-show area is enlarged. Return protection lasts 250 ms, or Zen's sidebar keep-hover delay if longer. One timeout checks the final visible bounds after animation: the sidebar stays open when the cursor is inside it and can hide when the cursor is in page content. Exiting again uses the existing bounded window-exit guard. Disabling either toggle cancels the added protection.

## Apply to Zentral panels

**Apply Window Entry Reveal to Autohidden Panels** is a separate off-by-default checkbox requiring the master, window entry reveal and Autohide Panels. It reveals only an already open panel through that panel's docked window side and within its height. It uses the existing panel visibility API, hide delay, popup, typing and resize rules. It does not change launcher/ledge hover areas or their reveal delays.

**Only Enhance Panels When Not Pushing the Webpage** defaults to on. With it enabled, panel entry reveal and its return protection pause while the effective `bgalazka-push-page` state is true, including Triple View. They resume in overlay mode. This uses the resolved push mode rather than a hidden panel's temporary webpage space, so hiding and revealing cannot toggle the restriction back and forth. Switching into push mode during return protection releases that protection. Turning this restriction off allows the panel entry enhancement in either mode. The restriction does not disable ordinary panel autohide or affect tab sidebar entry reveal.

## Performance and cleanup

There is no polling or global mouse tracking service. Recent-exit age is checked on return, with no additional expiry timer. The sidebar reuses its existing movement listener and checks only a null flag when no exit is recorded. The panel attaches mouseover/mousemove fallback listeners only after a relevant exit, detaches both on the first return, and clears them on disable, push-mode restrictions, lifecycle cleanup and teardown. The entry listeners detach when their prerequisites are off. The push-state observer watches only one document-root attribute, only while the panel enhancement and restriction are enabled. The master disconnects it. Ordinary movement over a hidden sidebar performs no geometry reads. During return protection only two stored coordinates are updated; there are no per-event allocations, preference reads or geometry reads. Outside return protection, sidebar bounds retain the once-per-animation-frame cache and use Zen's non-flushing API where available. Each surface has at most one bounded return timer, never restarted by normal mouse movement.

Preference observers filter exact settings within observed prefixes. Panel-only settings do not reset sidebar protection, and slider changes do not restart current grace timers. The catalog descriptor uses one consistent owner, and `features/settings/layout.json` keeps the master, entry options, restriction and sliders in order.

## Validation

Simulated checks cover left/right entry, fast returns landing deeper inside, missing root entry events, expired exit memory, temporary-listener cleanup, quick exit/return, animation completion, wrong edges, normal inside movement, closed panels, native suppression, popup and control interaction, toggle dependencies, descriptor loading/order/defaults, push-mode transitions, Triple View's resolved push state, master off/on cycles, cleanup and high-frequency movement. Syntax checks cover all changed JavaScript. Unrelated archive entries are preserved byte-for-byte.

Live Zen validation is still required for native event delivery and animation. On both sidebar and panel sides, enter from outside, jerk out and back, use tabs and sliders, move into page content, switch push/overlay modes during return, and disable the master. Native event delivery varies by platform. Without either a delivered boundary entry event or a recent observed side exit, a deep inside cursor position cannot reliably identify which window edge was crossed. Recent exit memory is limited to 1500 ms and the matching window half; ambiguous opposite-side, top/bottom and outside-height returns are rejected. Live reliability is not established by the simulated checks.
