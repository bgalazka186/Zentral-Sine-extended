# Video preview and 1.1.0 integration follow-up

> Historical first patch. [VIDEO-PREVIEW-FOLLOWUP.md](VIDEO-PREVIEW-FOLLOWUP.md) supersedes its reserved-control-band layout, saved-position default, pointer capture, double-click handling and 100 ms window-resize updates. The user reported first-interaction and performance problems despite the initial fixture results.

This overlay is based on the uploaded chrome/sine-mods/zentral tree, not on an assumption that GitHub main has identical files. Its ZIP uses repository-relative paths: extract it into the existing zentral folder (or repository root), replacing matching files, then restart Zen. It contains changed files only and cannot install the mod by itself. Back up the existing mod folder first. No prefs.js, screenshots, other mods, app records, local paths or private browser preferences are included.

The Extended package remains 3.0.0 and its core reference is Zentral 1.1.0, commit `0e18990c0bfa2563d22de8f5d04135da186ef1b0`. This is the existing adapted/extracted base, not a claim that the original monolithic script is loaded unchanged. The existing BASE-PATCHES ledger and UPSTREAM-MAP remain the migration boundary. Replacing that entire base with an unadapted upstream master script would discard Extended contracts.

## Changes

- Window resize storms no longer reapply unchanged geometry or force a second visibility/capture pass for each event. Enlarged geometry updates are capped at one per 100 ms; capture scheduling, progress queries and caption fitting pause during interactive resizing and resume after a 160 ms quiet period. The existing receiver stays alive. Resize timers are canceled on close/destroy. This avoids the repeated work identified in source; real Zen resize smoothness still needs measurement.

- Fixed a lifecycle regression: starting an ordinary sidebar resize destroyed the enlarged controller permanently. Only final video destruction now destroys it.
- Enlarged input is delegated in capture phase, before an embedded native browser can take focus. Native receivers do not intercept enlarged pointer input. Pointer cancellation, lost capture, blur, resize and destruction release gestures correctly. First-drag/first-resize and reopen paths have fixture coverage; real Gecko input still needs confirmation.
- Aspect-ratio locking uses the selected source's display dimensions, with a 16:9 fallback. It applies to all eight resize handles and viewport changes. Caption/control trim is separate from the video dimensions. Captions add/remove card height rather than consuming image height, subject to viewport limits.
- Bottom-edge hover controls are optional; keyboard focus and an open source menu keep them accessible. Their space stays reserved, so hover does not cause layout changes. The normal sidebar remains unchanged.
- Default bottom clearance is 64 px, increased for detected bottom workspace controls. It is configurable in Video / Enlarged preview. Saved positions take priority; clear the remembered position to adopt the new default. Users can still move the player themselves.
- Alt+Q follows the existing configurable Insta Peek shortcut, including when Apps is disabled. Hold to make the enlarged card invisible and transparent to input. Key release, modifier release, window blur, close and destroy restore it. It retains geometry, source and renderer; no second capture pipeline is created.
- A working renderer is required before enlarging. Explicit source-visible suspension and strict native deferral close the enlarged card. Exhausted/unavailable capture methods and failed live receivers return it to the sidebar, retaining the ordinary retry/fallback policy and status. Missing Popover support leaves the sidebar usable. No unsafe reparenting of live browser elements was added.
- Missing or failing optional enlargement/caption-layout helpers no longer disable the whole video feature. Captions degrade to disabled when their presentation helper is absent; enlargement degrades to a no-op. Required transport/rendering failures still disable video through the existing feature boundary.
- Progress state queries run once per second only while the seek control is visible and usable. Queries share health deadlines and never trigger source scans or pixel capture. They stop for hidden controls, minimized windows, compact suspension, temporary hiding, stopped sessions and teardown. Keyboard focus no longer freezes progress forever; active range manipulation still defers updates. Infinite/invalid durations hide seek controls. Direct state queries validate the source identity payload.
- Frame/basic YouTube caption observers confine character and attribute observation to caption surfaces and the subtitles toggle, while watching player structure for replacements. Native cue events and bounded recovery remain. Text fitting caches include width and skip empty/inactive bands. These use the existing engine; no authenticated timed-text fetching or private page URL collection was added. Reference reviewed: Firebolt9907/Zenslop at `b5ce39ede14a09c0095aa822ea380cbca8d236f0`.
- New settings appear in their owner section and grouped copies in New settings / 3.0+. Copies use the same preference keys. Both compatibility switches remain optional when Zentral Groups / experimental Library resizing are disabled. Companion mods are not modified.
- Recommended settings adopt portable, schema-validated preferences from the supplied profile. Personal data, custom URLs, logger paths, app registrations, screen offsets and remembered enlarged geometry are excluded; applying Recommended also preserves remembered geometry. Defaults retain automatic fallback, periodic discovery, source-page protection and experimental legacy capture disabled. Recommended intentionally retains the supplied event/manual discovery choice, 160 px still/stream width, 10 FPS canvas stream, 250 ms caption recovery, one-line scrolling captions and source-visible suspension.
- Loader reports now show controller constructions separately from evaluated sources. Failed evaluation removes its own partial definitions without discarding successfully loaded child sources. Failed factories cannot subsequently be required. The same contracts apply in the standalone video loader. The runtime supports synchronous verification before marking a feature active; video verifies that its public diagnostic and teardown APIs exist.
- Fixed the provenance generator for files without a final newline: it now emits the required Git marker rather than joining the next file header to the preceding hunk. The regenerated patch was applied to a clean snapshot and its output compared byte-for-byte with the adapted base.
- Restored five advertised pristine snapshot files from the exact pinned upstream commit; all eight manifest hashes now match. Regenerated the adapted-base diff. Original sources are never loaded alongside the active base.

## Settings

All three additions are in **Video playback / Enlarged preview** and mirrored in grouped **New settings / 3.0+** rows, including Sine declarative preferences:

| Preference suffix under zen.workspace.zentral.video_preview. | Default | Purpose                                                                |
| ------------------------------------------------------------ | ------- | ---------------------------------------------------------------------- |
| enlarged_keep_aspect                                         | true    | Keep the selected video ratio during resizing.                         |
| enlarged_hover_controls                                      | true    | Reveal bottom controls near the bottom edge or keyboard focus.         |
| enlarged_bottom_gap_px                                       | 64      | Initial bottom clearance; detected workspace controls can increase it. |

Insta Peek reuses `zen.workspace.apps.insta_peek.shortcut`; it has no second shortcut setting.

## Verification and remaining limits

All 12 local Node test groups pass. Local Node fixtures cover first drag, each resize edge/corner, free resizing, caption trim changes, viewport reduction, cancellation, reopen, saved geometry, fullscreen ownership, Alt+Q/custom chord and releases, optional-helper loss, seek focus/live duration handling, loader partial-registration rollback and failed construction. Resize-storm fixtures check bounded work, final bounds, caption/capture scheduling and timer cleanup. A candidate-policy matrix checks renderer choices, strict mode, source visibility and absent APIs. Syntax and JSON checks cover the installed source tree; preference generation and pinned-reference/adapted-patch checks are also run.

These fixtures do not exercise privileged Gecko browser elements, OS input, DRM, real YouTube caption timing or combinations of companion mods. No Zen binary is available in this environment, so native-clone recovery and actual first-interaction behavior still require live confirmation. No measured CPU or caption-latency improvement is claimed.

Before publishing, test a cold start and second window, then all resize handles on native and still capture; source tab reveal/hide; strict mode and source-visible suspension; unavailable/DRM sources; disabled/deleted optional helpers; subtitle toggle; compact/minimized windows; pointer and keyboard seeking; Alt+Q release/blur with Apps on and off; fullscreen; and restart with saved geometry. Ctrl+Alt+= opens settings, or bootstrap diagnostics if startup is unavailable; use `ZentralModuleLoader.report()` for controller-construction details and `ZentralVideoPreview.diagnostics()` for the actual selected renderer. A loaded source is not proof of successful native presentation.
