# OW-123 — Standalone and feature-ownership audit

Static audit on 3.4.0 after OW-122. The request is to list issues only: no reported feature code was changed for this audit. Locations below are source files; the standalone bundles are generated from those sources. Findings describe specific unavailable behavior, not a claim that an entire mod fails to start.

## Findings

1. **Boost's interactive UI and limiter messages are owned by Widgets.** The Boost standalone package (`additional/boost/standalone.json`, `theme.json`) contains Boost and tab policy, not the Widgets tray. The RAM display, Light/Deep/Game/Restore actions and limiter-result toasts are registered in `additional/widgets/ZentralWidgets.uc.js:5077–5395`; the only shortcut in `additional/boost/ZentralBoost.uc.js:918–967` is for Light and defaults to empty (`additional/boost/preferences.json`). With only Boost installed, or with Widgets removed/disabled in the full pack, startup trim, settings, limiter and the programmatic API still exist, but the card, on-demand RAM display, manual Deep/Restore controls and widget limiter notifications do not. Game Mode remains selectable through its preference. This is a concrete ownership/dependency gap, not an initialization failure.

2. **Widgets offers an enabled Boost card without its provider when Widgets is installed alone.** `additional/widgets/standalone.json` includes no Boost implementation; `ZentralWidgets.uc.js:5084–5101` resolves only `window.ZentralBoost`, yet registers the Boost widget enabled by default. With no Boost, the reading is unavailable and `runLight`, `runDeep`, `runGameMode` and `runRestore` return without performing the corresponding action (`:5236–5318`). The rest of Widgets is independent. This is the reverse user-visible consequence of finding 1, not a second missing service implementation.

3. **Standalone Game Mode's pause contract depends on the full runtime and does not coordinate separate standalone packages.** `loader/standalone/ZentralStandaloneShim.js:107–148,276` constructs a new private performance switch for each standalone bundle and assigns that bundle's shim to `window.__zentralStandaloneRuntime`. Boost instead reads only `window.ZentralRuntime?.performance` (`additional/boost/ZentralBoost.uc.js:1176,1352–1355`), which is absent in a standalone-only installation. Widgets (`additional/widgets/ZentralWidgets.uc.js:2910`), RSS (`additional/rss/ZentralRssDisplay.uc.js:167`) and Video (`additional/video/ZentralVideoPreview.uc.js:3272`) also consult only the full runtime. Notes uses its captured shim (`additional/notes/ZentralNotes.uc.js:32373–32380`), but that is a different instance when installed as a separate standalone package. Thus standalone Boost can still run its deep/activity pass but cannot publish the advertised pause to the other standalone mods; its own `paused` status remains false. This is separate from normal optional behavior when there are no other features to pause.

4. **Notes' web-panel slot and reveal integration is partly implemented in panel-owned files.** Notes writes the reserve/gap and dispatches events in `additional/notes/ZentralNotes.uc.js` (`applyPush`, `createBarAdapter`, and the reveal request near line 36319). The rules that actually make the page yield space and open the Triple divider gap are in `extension/panels/browsers/ZentralBrowserIntegrations.css:485–516`; the panel's geometry/floating code consumes the reserve, `extension/panels/secondary-views/ZentralSecondaryViews.uc.js:276–283,376,476` consumes the gap, and `extension/panels/interaction/ZentralPanelHover.js:465–483` handles the reveal request. Those effects are not contained in the Notes standalone stylesheet. If a compatible panel host is present but the corresponding integration is absent, Notes' event/variable alone cannot produce the same slot or reveal behavior. The panel coordinator currently declares browser-integrations as required and secondary views as optional, so removing the former normally blocks the panel suite itself; this is a boundary/conditional-integration risk, not a demonstrated crash in an otherwise intact full pack. When no panel is present Notes deliberately uses its standalone card.

5. **Library/panel and tab-group compatibility are controlled by a Video-owned preference.** `zentral/apps/controllers/ZentralLibraryCompatibility.js:136–154,283` observes `zen.workspace.zentral.video_preview.disable_experimental_bridge` to decide whether to attach the optional native Library animation bridge. `zentral/groups/controllers/ZentralGroupsNativeAdapter.js:724–741` uses the same Video preference to decide whether to exclude Library copies from tab-group queries. The setting belongs to `additional/video/settings.json:2315`, with fallback `true` when missing. Consequently removing Video's settings or changing a Video experiment changes unrelated Library/panel and tab-group compatibility behavior, even though the core DOM collision fallback still exists. This is an ownership/coupling issue; the actual effect on a particular Zen build and preference state needs live verification.


## Related disable-switch defect (not a misplaced-code claim)

- **Boost's main enable switch is declared but is not read by its implementation.** `additional/boost/settings.json:10` exposes `zen.workspace.zentral.boost.enabled`, and `additional/boost/ZentralBoost.uc.js:30` defines `PREF.ENABLED`; there is no use of that constant or other read of that preference in Boost's source. The Widgets card uses a different `zen.workspace.zentral.widgets.boost.enabled` preference. Static evidence therefore indicates switching the Boost enable setting off does not stop the Boost API, startup trim, limiter or game-mode machinery. This directly affects the requested feature-disabled scenario, but is listed separately because it is not itself evidence that code was placed in another feature. Runtime verification is still needed.

## Reviewed, not counted as confirmed failures

- `additional/tabs/ZentralTabDensity.css:929–980` and `zentral/groups/styles/ZentralGroupsInjected.css:347` contain Notes/Agenda/RSS-related pending-row styling outside their feature. Notes now has its own scoped pending-row overrides in `additional/notes/ZentralNotes.css:3656–3845`; the tab-density rule also affects compact-tab layout. Treat this as an ownership/redundancy candidate, not a proven current missing fix; third-party styles and real Zen cascade were not available here.
- `extension/appearance/ZentralAppearance.css` has extensive video-specific atelier styling. The Video package also has its own stylesheet and standalone look adapter (`additional/video/ZentralVideoPreview.css:906+`, `additional/video/standalone/ZentralVideoControlsLook.js`), so ownership alone does not prove a missing behavior. Visual parity after removing Appearance needs a real-browser comparison.
- The widgets calendar opener and Notes language, the widget/video sizing handshake, Notes/folder-color bridges, and the tab policy are guarded or have explicit standalone copies/fallbacks. A cross-feature reference by itself is not proof of a fault. The tab policy is embedded by both Boost and Tab Unload manifests.

## Scope and limits

Reviewed the feature catalog and stylesheet owners; standalone manifests, bootstrap/shim, shared tab policy, settings and generated-package configuration; cross-feature references in `additional/`, `extension/`, `loader/`, `zentral/`, and relevant CSS. This is static code inspection plus the repository's existing tests, not exhaustive live execution of every feature-removal combination or third-party theme. Therefore it identifies the evidenced cases above and candidates, but cannot certify that no other misplaced code exists. A Zen/Sine install/uninstall matrix and visual checks remain necessary before claiming full independence. No audit finding was fixed.
