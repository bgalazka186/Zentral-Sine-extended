# Corrective follow-up to the first video repair

Apply this changed-files ZIP on top of the previous `Zentral-Extended-1.1.0-changed-files.zip`: extract into the existing `chrome/sine-mods/zentral` folder or repository root and replace matching files, then restart Zen. It contains only this follow-up's changed files. The mod remains Extended 3.0.0 with the same Zentral 1.1.0 base pin.

The first patch passed local fixtures but the user reported persistent first-click trouble, broken double-click return, misplaced opening geometry and unsatisfactory performance. Those fixtures did not model real click retargeting or privileged Gecko hit testing. Their success did not establish that the live bugs were fixed.

## Changes

1. **Sidebar width across restart:** the opt-in startup sidebar recalculation previously wrote temporary dimensions into native persisted width/style attributes. It now uses a removable stylesheet and an owner-specific marker. It never writes the native width attribute or inline styles, including during cleanup. Native changes made during startup therefore cannot be overwritten by an old snapshot. A divider press cancels the temporary style before native resize handling. This removes a plausible mod-induced race; it does not claim to fix every native or third-party sidebar persistence issue.
2. **Opening position:** every opening uses the sidebar-side bottom corner and configured workspace clearance by default. Native right-side flags work as boolean attributes as well as string values. Old remembered coordinates are ignored unless the new **Remember enlarged preview position** switch is enabled. Size remains remembered. This avoids carrying a position from a differently sized window/monitor into the default placement. No preference clearing is needed to adopt the new default.
3. **Overlay controls:** controls and the progress range share one wrapper positioned at the bottom of the video image. Its background is `rgb(0 0 0 / 40%)`. It does not reserve a controls band or change the image size on hover. Keyboard focus in the controls keeps it visible; merely focusing the player does not. Controls are above the hit layer; resize grips are above both. The wrapper contains no live browser and returns intact to the sidebar when enlargement closes. The separate subtitle band stays below the image.
4. **First press and double-click routing:** the previous implementation captured pointerdown on the card but listened for double-click only on the hit layer, which could redirect the click target away from its listener. Capture is now delayed until actual movement crosses the dead zone, then belongs to the pressed image/grip. A normal image press is not canceled, preserving native click targeting. Double-click is handled on the card in capture phase and ignores controls/grips. The player explicitly receives chrome focus after opening. A press retargeted to the popover itself is accepted as a move or border-resize gesture. Hit-layer positioning/stacking are protected against sidebar appearance rules. This addresses identifiable event-routing flaws; the reported first-press behavior still requires real Zen confirmation.
5. **Resize work:** while the OS/browser window is being resized, the live receiver keeps a fixed pixel size. One final fit occurs after 160 ms without a new resize event, rather than repeatedly resizing a content browser at 100 ms intervals. Manual move/resize geometry is coalesced at 32 ms; capture/progress/layout work is suspended during an actual player resize and resumed once it ends. Pure movement does not trigger image capture. No measured browser-wide performance improvement is claimed.

## Settings and ownership

`zen.workspace.zentral.video_preview.enlarged_remember_position` defaults to false. It is in Video playback / Enlarged preview, the grouped New settings mirrors, and generated Sine preferences. The Recommended preset also keeps it off. Existing saved coordinates are retained for users who enable it. No second shortcut or capture pipeline was introduced. Video changes remain in `additional/video/`; the nonpersistent startup repair stays in `additional/tabs/compact-hover/`.

Native persistence behavior was checked against Zen's `src/zen/common/sys/ZenCustomizableUI.sys.mjs` at desktop commit `c0dffc17681ac25b5dfcc8da0c3f238f384987a6`: startup reads the toolbox width attribute and manual resizing updates width/style. The repair avoids mutating these fields rather than attempting to own native persistence.

## Validation

All 18 local fixture groups pass. Local fixtures now cover click preservation before movement, first-gesture capture target, card-targeted double-click return, control exclusions, default versus opt-in remembered placement, boolean right-side flags, overlay-wrapper restoration, and startup repair completion/manual interruption/shutdown with persisted width unchanged. They also retain earlier geometry, optional-file, visibility-policy, Alt+Q, fullscreen and timer-cleanup checks. The changed sources and all installed JS/JSON schemas are checked; preferences and mirror metadata are regenerated and validated.

These are behavioral fixtures, not real Gecko or visual tests. No Zen binary is available here. In particular, first-press behavior, actual popover stacking, overlay appearance and smoothness must be checked in the user's browser. The startup test proves that this repair does not write or roll back native persisted dimensions; it cannot prove unrelated browser/mod persistence behavior.

No profile, screenshot, saved apps, personal URLs or other mods are included in this ZIP. See `REPAIR-FILES.json` for follow-up file hashes. The earlier repair note is retained as history and marked superseded where its behavior changed.
