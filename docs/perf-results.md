# Perf results (RAM plan `OW-87`–`OW-94`)

Source: `docs/PLAN_CODING_AGENT.md` (the owner's own measurements, 2026-11-18). One line per task, appended when the
task ships. **The owner measures effect on his machine; every figure here is "not measured" until he does.** The
point of this file is that a later session can see what changed and what it was expected to do — never a number
nobody took.

| Task | What changed | Expected effect | Measured |
| :--- | :----------- | :-------------- | :------- |
| `OW-87` | `zen.workspace.zentral.debug.core` defaults to `false` in the schema, the preset and Core's fallback table; the logger honours the pref instead of hardcoding the core category on; the settings switch reads and writes it | a fresh install collects no debug lines by default, so the logger does no string work for them | not measured |
| `OW-88` | Notes/Agenda sidebar placeholders are discarded after creation, after a session restore and after a click is answered (`parkPseudoTab`, one draining task + a bounded 3-try retry), behind `zen.workspace.zentral.notes.park_pseudo_tabs` (default on) | each live placeholder stops holding a content process: the owner measured ~11 of them at 43-51 MB each (~0.5 GB), so this is the biggest item that lives in Zentral code; rows, labels, icons and clicks are unchanged | not measured |
| `OW-89` | new `additional/boost/` (feature `boost`, catalog beside `tab-unload`, settings category `boost` · `Memory`): `memoryMB()` sums parent + child processes from `ChromeUtils.requestProcInfo()`, `runLevel1()` = `minimizeMemoryUsage` → `forceGC` → `forceCC` with the after reading 3 s later, one quiet trim per start behind `zen.workspace.zentral.boost.startup_trim`; no `setInterval` | the reading is a real total instead of a guess, freeing memory closes nothing, and the single startup trim costs one GC/CC pass 90 s after input stops | not measured |
| `OW-90` | the sidebar cards: the `status` card (battery + memory, off by default) is removed and the new `boost` card replaces it — RAM number, click = Level 1, 4 s toast, inline menu; it reads nothing itself and has `refreshMs: 0` | one fewer card that sampled the platform on a five-minute cadence and, on a desktop, had no battery to show; the RAM number and the action that lowers it now sit in one card that is awake only while open | not measured |
| `OW-91` | `loader/ZentralTabPolicy.js` is one answer to "may this tab be unloaded?" for TabUnload and Boost; Boost's deep pass sleeps eligible tabs oldest-`lastAccessed` first plus only `asleep-allowed` panel records, with an in-memory Restore (cap 50), panel `backgroundMode` saved with the app settings, and one optional shortcut for the light pass | a deep run can give back whole content processes for pages nobody has looked at in hours, without touching what is audible, sharing, selected or playing — and Restore puts the panels back on demand | not measured |
| `OW-92` | RAM limiter behind `boost.limit_enabled` (off): a pure `decideLimiter` (60 s idle cadence, 10 s above 70 % of the limit, cooldown, soft vs hard) and a one-shot chain that calls the deep pass in batches of three, stopping at `limit_mb × target_pct / 100`, bounded to 12 rounds, with one nag per ten minutes | a browser over the person's own limit gives memory back in steps and reports it, instead of growing until the machine swaps — and nothing is touched while the reading is under the limit | not measured |
| `OW-93` | a panel record marked `throttled` is `docShellIsActive = false` and `renderLayers = false` while hidden (and active again when shown), in `syncAppPanelBrowserActivity`; the preload path no longer forces such a record active, and the tile menu's switch applies immediately | a hidden, preloaded non-notification page stops burning ~35 % of a core (the owner's own measurement) while its browser stays loaded, so its sockets and badge events still arrive; `live` records are untouched | the owner measured ~35 % of a core for arena.ai; to be re-measured live after the owner sets it to `throttled` |
| `OW-94` | `ZentralRuntime.performance` (a pause switch every repeating feature subscribes to: video discovery, widgets, RSS, Notes' minute wake, the panel fallback poll) plus Game Mode, a toggle that runs Level 2, pauses every subscriber and idles every tab/panel browser except an audible tab, the video source and the selected one | while the owner games: no discovery scan, no widget refresh, no RSS scan, no minute wake, no fallback poll, and no compositing or timer work from the tabs they are not playing — the plan's ~35 % of a core for a hidden arena.ai and the widget/video timers on top | not measured; to be measured live during the owner gate (game + Game Mode on, watch CPU in `about:processes`) |
| `OW-111` | Boost's deep pass builds a `Set` of Essential-panel record tabs once, leaves them to the panel loop, and asks the shared tab policy with `isPanelRecord`/`panelConsent` so each record's `backgroundMode` is the consent (`asleep-allowed` may sleep while pinned; `live`/`throttled` stay loaded; Stronger saver may sleep all); one new suite + realistic pinned fixtures in `ow-91` | no extra memory is freed by itself, but a deep pass no longer double-counts or wrongly unloads record tabs, and an `asleep-allowed` pinned/Essential record can finally give back its content process with the default pref | not measured |
| `OW-112` | renamed Boost's pinned-tab pref `keep_pinned` → `unload_pinned` with a one-time migration and a one-release read-only fallback; the pref service is consulted once per deep run instead of once per tab | no runtime performance change intended; one pref lookup per deep pass instead of one per tab, and an owner's existing choice survives the rename without a second checkbox | not measured |
| `OW-113` | the video preview publishes a live getter over its existing `current` source state (`window.__zentralVideoSourceTab` / `ZentralVideoPreview.sourceTab()`), removed on destroy; Boost's existing `video-source` never-rule becomes live code | no new timers, listeners or scans; a paused/muted video source keeps its content process loaded instead of blanking the sidebar preview, so the deep pass may free slightly less RAM in that case | not measured |
| `OW-114` | screenshot-free audit of all `[pending]` CSS candidates plus eight narrow Notes/Agenda overrides in `ZentralTabDensity.css` that restore opacity/filter/row layout for parked placeholders | no runtime cost; a static CSS audit and a few extra stylesheet rules, with no new listeners/timers. Visual effect (labels, icons, opacity, grayscale, spacing) is an OWNER GATE, not measured here | not measured; owner compares sidebar rows before/after |
