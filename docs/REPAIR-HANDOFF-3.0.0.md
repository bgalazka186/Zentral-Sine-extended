## Captions: responsiveness, presentation and resources

The selected recovery interval is now honored; the old hidden three-second floor is removed. Your supplied preferences have `caption_poll_ms=3000` and `captions_visible=false`. These were **not rewritten**: choose 250 ms in Video subtitles or New settings · 3.0+ and enable the subtitle toolbar button when evaluating latency.

Frame cue/DOM events are coalesced without the old added 50 ms delay. Caption readers now exclude hidden descendants, so rolling YouTube text is read more like Zenslop's visible-text extraction. Native text-track and actor/poll fallbacks remain supported. The inspected Zenslop reference uses event-driven delivery plus a caption clock; this repair adapts the relevant behavior, not its entire renderer. The source reference already pinned in UPSTREAM.json was inspected; this is not a claim to track every later upstream commit.

The separate band reserves its configured space while active, including between cues. Text is explicitly white and uses a real inner line clamp. **One line** is selectable. The default Fit mode reduces the glyph size down to 8 px for long cues, then uses an ellipsis if they still cannot fit; it never shows a partial third line. Scroll mode preserves the selected font size and all text within a scrollable band. The full cue is also available as the title. A fixed small band cannot display arbitrarily long text at a fixed font size without fitting, truncating or scrolling; the setting makes that tradeoff explicit.

Caption fitting is cached by text/settings and invalidated by the existing picture resize observer. The presentation factory is shared; it does not allocate a new measurement canvas for every cue. The former “3 second recovery” power toggle is relabeled and now throttles watch rebinding (5 seconds vs 1 second), without overriding the recovery interval.

Turning captions off stops the caption polling timer, disconnects frame observers/cue listeners, cancels queued caption publication and rejects late results. A single already-in-flight IPC may finish, but it cannot restore visible captions or retain a new watch after disable. Video preview rendering remains independent.

## Architecture audit and next update

The requested four trees are retained:

| Tree          | Owner                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------- |
| `loader/`     | Single entry, readiness, feature/CSS graph and settings host                                |
| `zentral/`    | Existing adapted 1.1.0-reference base, compatibility bridge and immutable upstream snapshot |
| `extension/`  | Panel policy, gestures, secondary views, pill actions, launcher policy and settings views   |
| `additional/` | Independent video/captions, native sidebar guard, RSS, tab and Library tools                |

The base API edits are B001's read-only `controls` reference bundle, B015's optional launcher-placement policy callback and B016's narrow hosted-browser identity selection for live slot swaps. It does not put caption, gesture, hold-action or settings-lab logic into the base. `ZentralPillActions.js` and `ZentralReleaseLab.js` keep those responsibilities separate.

However, the active base still includes substantial **inherited Extended adaptations and extraction**, as documented in BASE-PATCHES.md. It is not yet a pristine upstream monolith with only a handful of API lines. Renaming it would not make that true. Replacing it all at once would risk Essential/native-tab identities, containers, notifications and secondary views—the very regressions being repaired here.

A safer next stage is to formalize browser-host lifecycle and enumeration methods in the bridge, replace one legacy wrapper family at a time with owned hooks, then build an upstream-source API adapter behind the same contracts. Keep only one Apps instance and one geometry owner. Require live tests with your profile plus a clean profile before replacing the adapted lifecycle. Never enable the archived reference script alongside the working base.

Options for the owner to decide later: (1) retain the adapted base and keep explicit upstream diffs (least migration risk), (2) incrementally converge to an upstream file with a small API patch (more work, easier later rebases), or (3) a fully external interception extension (small upstream diff but brittle private-method/DOM dependencies). Option 2 remains the direction recommended by the chosen hybrid architecture; this repair takes small steps toward it without replacing the current browser owner.

## Remaining decisions

Keep the selected single-line/Fit or Scroll subtitle policy according to readability needs. The fixed-height band cannot fit arbitrary long speech at a fixed readable font size; Fit reduces to 8 px and then truncates, while Scroll retains the full text/font. A future separately fetched caption clock, like Zenslop's optional timed-text path, is a larger feature with authenticated/session-bound YouTube requests and separate cleanup; this repair fixes the current visible-text/event pipeline instead. For an actual OS-level enlarged PiP window, use native PiP or decide on a separate window implementation later. The current Fullscreen control temporarily fills Zen’s window and enters native window fullscreen, preserving the previous window state.

The shared docking calculation is independent of the pointer grab offset. Move/Resize, the primary toolbar grip, Super Pin's grip and Triple View's lower-toolbar grip all resolve to their owning host. URL fields and unrelated action buttons are not move targets. The pill grabber retains its separate width/pill-offset role. These distinctions are covered by focused gesture checks.

The end-to-end request inventory, including explicitly incomplete work, is in `REQUEST-AUDIT.md`. The separate configurable Attach/Detach pill action is restored; it reuses the existing placement owner.

Overflow docking uses the panel edge near the normal safe boundary, not the extended off-window clamp boundary. No extra push is required in this mode. Moving beyond the snap zone leaves the panel floating partly outside; the 15 px penetration policy remains for bounded panels. Both policies use the same host/gesture owner across panel types.
